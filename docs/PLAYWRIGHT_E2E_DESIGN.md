# Browser E2E Adapter — Playwright Design

**Status:** PROPOSED; priority MEDIUM. Not implemented. Normative dependency: [INTEGRATION_CONTRACT_V0_1.md](INTEGRATION_CONTRACT_V0_1.md).

## Purpose

Verify an actually running web application after coding changes, through browser interactions, assertions, screenshots and browser diagnostics. This is optional and must not delay the higher-priority read/edit/test/Git integration. Do not confuse browser E2E with API contract tests: both remain required.

## Ownership and boundary

- **Host backend wrapper:** may display task status, references to approved E2E artifacts, and relay user approvals. MUST NOT import Playwright, start browsers, run web servers, read screenshots directly from workstation paths, or interpret browser tests.
- **Coding Agent Service:** decides whether E2E is necessary, chooses a declared test profile, budgets retries and time, manages artifact references and evidence; does not own a browser process.
- **Local Agent Playwright adapter:** resolves the registered project/browser profile, launches a bounded owned process, starts/stops an allowlisted application test server when necessary, owns the browser lifecycle, records assertions, screenshots, console errors, network failures, trace and exit status. It may run only under workspace policy.
- **Frontend:** displays results and safe artifact references; never receives filesystem access or a direct localhost execution token.
- Browser content (DOM, logs, pages) is untrusted, not a source of instructions for the agent.

## ToolPort interface (proposed)

`capabilities()`: report `browser_e2e` only when runtime, browser binaries and profile are available.

`run_browser_e2e({task_id, operation_id, workspace_id, profile_id, expected_revision, approval_id, artifact_policy})` -> `{status, exit_code, test_count, pass_count, failure_count, duration_ms, stdout_ref, stderr_ref, screenshots, trace_ref, browser_console_ref, observed_revision, truncated}`.

- `profile_id` maps to an allowlisted workspace-local config; no arbitrary user-supplied shell strings, browser URL, host file paths or command.
- Require expected revision/worktree snapshot verification; mismatch -> conflict, not a misleading PASS.
- Allowed status: `PASS`, `FAIL`, `TIMEOUT`, `CANCELLED`, `UNKNOWN`, `UNAVAILABLE`.
- Evidence refs are bounded, immutable, authenticated, scoped and expiring; do not leak raw local paths to host.
- Operation id is allocated before execution and tracked in local journal. A lost response must not trigger duplicate E2E as an unintended effect.

## Isolation / safety requirements

1. Bind a test server to loopback or isolated container networking; never expose a dev app to public network automatically.
2. Restrict browser navigations and outgoing requests to an allowlisted origin set, unless explicit approval broadens it. Protect loopback/private IP targets and cloud metadata endpoints from SSRF.
3. Use isolated browser contexts with fresh temporary user data; no access to the user's normal browser profile, credentials, extensions or cookies.
4. Explicit allowlist for test commands/Playwright scripts. No arbitrary TypeScript/Python snippets generated by the model and executed without approval.
5. Set process, server-start, test and browser timeouts; maximum retries 1 unless policy overrides. Kill owned process trees on cancellation; preserve a bounded diagnostic tail.
6. Limit concurrent browsers, screenshot count and pixel/byte size. Default concurrency one to reduce resource contention.
7. Screenshots and traces may contain personal information or secrets: scrub where feasible; retain locally by default, export only with scoped grants and retention limits. No upload to public GitHub.
8. Validate that the expected test URL belongs to the authorized workspace test profile; refuse remote production URLs by default.
9. No automatic Git commit or push based solely on a visual screenshot. Treat screenshot interpretation as advisory; assertions and exit status are independent evidence.

## Test pyramid and scheduling

- **High priority:** unit/syntax and service↔Local Agent contract tests always on relevant changes.
- **High priority:** focused integration tests for changed tool/API boundaries.
- **Medium priority:** browser E2E when UI, rendering, navigation, accessibility or browser-side behavior changed, or requested explicitly.
- **Low priority:** full browser suite on release candidate or explicit operator request.

Default E2E: only changed-coverage/profile-tagged spec files; full suite requires explicit trigger. A screenshot without assertion is observation, not PASS evidence. For visual regressions, compare against versioned baseline with tolerances and report changed regions.

## Acceptance tests

| ID | Scenario | Required behavior |
| --- | --- | --- |
| B01 | Working local example app and one Playwright spec | PASS with actual exit code and test counts |
| B02 | Deliberately broken selector/assertion | FAIL, diagnostic and screenshot references |
| B03 | App server cannot start | FAIL/UNAVAILABLE, no fabricated PASS |
| B04 | Browser binaries missing | UNAVAILABLE with install guidance; chat remains working |
| B05 | Timeout or cancellation | Owned processes terminated; actual state reported |
| B06 | Host tries arbitrary URL/command | Rejected without execution |
| B07 | Attempt to reach disallowed origin | Blocked and recorded |
| B08 | Concurrent E2E requests | Serialized or bounded by configured slots |
| B09 | Agent is removed / browser adapter disabled | Core read and chat remain operational |
| B10 | Reconnect / duplicate operation ID | One recorded operation; no accidental duplicate run |
| B11 | Screenshot/trace contains sensitive information | Scoped artifact access, no public exposure |
| B12 | Modified source revision between plan and run | CONFLICT, no stale success claim |

**Definition of done:** Local Agent adapter, explicit profile schema, at least one fixture web app, browser-installed E2E execution, failure-path tests, collected evidence, and host-neutral contract tests all pass. Until then, mark `browser_e2e` unsupported in capability discovery.
